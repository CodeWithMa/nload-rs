## Findings in brief

1. Current candidates are **crossterm 0.29.0**, **libc 0.2.189**, and **signal-hook 0.4.4**. Their relevant Linux dependency graphs offer GPL-2.0-only-compatible licensing by using **MIT** where an alternative exists. Apache-2.0 alone is incompatible with GPLv2-only; an `OR` alternative is important. [S1–S4][S8]
2. Crossterm with `default-features = false, features = ["events"]` provides synchronous timed input, arrows and resize events without an async runtime. It internally uses **signal-hook 0.3.18**, **signal-hook-mio 0.2.5** and **mio 1.2.3** in the examined compatible-version graph. Adding current signal-hook 0.4.4 introduces a second signal-hook version, but their registry dependency can be shared. [S2][S5]
3. Full raw mode clears `ISIG`: typed Ctrl+C and Ctrl+Z become input bytes/events, not terminal-generated SIGINT/SIGTSTP. Explicit Ctrl+C input handling **and** external SIGINT/SIGTERM notification are both needed. Ignoring Ctrl+Z input is straightforward. [S6][S9]
4. `libc::clock_gettime(libc::CLOCK_BOOTTIME, ...)` is a stable-Rust mechanism for the agreed suspend-aware elapsed time. `Instant` does not provide that Linux clock contract. A BOOTTIME timerfd is available if a unified Linux FD loop needs suspend-aware deadline wakeups. [S12–S15]
5. **The unconditional prior-cursor-visibility assumption is not established.** Crossterm has Show/Hide but no visibility query or saved prior value. Xterm DECRQM and private-mode save/restore can support exact restoration on supporting terminals. Neither is universal; Linux v6.12's virtual console supplies a concrete counterexample and also lacks the xterm alternate buffer. “Show on exit” is not “restore prior visibility.” This requires a human support/fallback decision in the architecture conversation. [S7][S10][S11]
6. Whole-list `/proc/net/dev` acquisition is feasible without an additional crate, but read bytes through EOF and preserve raw name bytes. The existing [Linux-counter research](linux-counters.md) remains valid: bulk does not mean one syscall or atomic accounting. [S20–S22]

## 2. Raw mode and keyboard behavior

**Documented:** `cfmakeraw` clears ICANON, ECHO, ISIG, IEXTEN, IXON and output postprocessing among other flags. With ISIG enabled, VINTR (normally 0x03/Ctrl+C) generates SIGINT and VSUSP (normally 0x1a/Ctrl+Z) generates SIGTSTP; with ISIG cleared those controls can be read as bytes. “Noncanonical” alone is not sufficient to disable signal generation. [S9]

**Implementation:** crossterm 0.29.0's default Unix backend uses rustix `Termios::make_raw`; its libc feature uses cfmakeraw. Its input parser converts bytes 0x01–0x1a into `KeyCode::Char('a'..'z')` with CONTROL: Ctrl+C is Char('c')+CONTROL; Ctrl+Z is Char('z')+CONTROL. It parses both CSI arrows (`ESC [ A/B/C/D`) and application-cursor SS3 arrows (`ESC O A/B/C/D`). Default legacy key decoding creates Press events; an enabled enhanced keyboard protocol can also distinguish Repeat/Release. [S6]

**Inference for the confirmed behavior:** map the Ctrl+C key event to the same cleanup/status-130 exit path as externally delivered SIGINT. Consume/ignore Ctrl+Z; it will not suspend through the terminal driver in full raw mode. SIGINT/SIGTERM sent by another process still need handlers/notification. An externally sent SIGTSTP is a different event from typed Ctrl+Z; the prior agreement does not establish its policy. Full raw mode also stops terminal generation for Ctrl+backslash/SIGQUIT, and clears IXON so Ctrl+S/Q do not accidentally freeze/restart output. A custom direct cbreak implementation could keep ISIG and disable VSUSP, but would need an explicit VINTR/other-control policy; it is not required to obtain the agreed full-raw behavior. [S6][S9]

## 3. Synchronous polling, resize and wakeup

**Documented:** crossterm `poll(Duration)` returns whether an Event is available within the timeout; true guarantees a following `read()` will not block under the supported single-reader usage. `read()` alone may wait indefinitely. Poll/read must be used on the **same thread**, and must not be mixed with EventStream. Resize is `Event::Resize(cols, rows)`. [S6]

**Implementation:** the events-only Unix source lazily creates a mio Poll, registers terminal input and a signal-hook-mio subscription to **SIGWINCH only**, and queries the size on notification. It does not subscribe to SIGINT/SIGTERM, and exposes no public synchronous API to register another FD or wake its private poller. An unrelated OS signal can interrupt mio, but crossterm catches `Interrupted` and retries, so it is not an exit notification API. The internal Waker is feature-gated/private, used by EventStream; enabling that feature does not give callers a public synchronous wake handle. [S6]

**Documented/implementation:** TIOCGWINSZ returns kernel-maintained dimensions; a change sends SIGWINCH to the foreground process group. Crossterm `window_size()` tries `/dev/tty`, then stdout if opening it fails. `size()` additionally falls back to spawning `tput cols`/`tput lines` if the ioctl path fails. Raw/input selection normally uses terminal stdin, else `/dev/tty`. Consequently terminal stdin/stdout should still be explicitly checked by the application, and two unrelated terminal FDs are not made identical by those checks. On a normal foreground PTY session the paths coincide; this is an assumption, not a capability test for arbitrary terminals. [S6][S16]

Feasible notification/wait mechanisms (**inferences**, not chosen architecture):

| Mechanism | Can wake what? | Constraints |
| --- | --- | --- |
| signal-hook `flag::register` / `register_usize` | Sets an Arc atomic; does **not** wake crossterm's poll | Use finite waits and inspect flags before/after events. register_usize can retain a signal-specific status rather than lose INT/TERM distinction. It stores each arrival, not a guaranteed first-signal-wins arbitration. |
| signal-hook `Signals` iterator (`iterator` feature) | Wakes its own self-pipe wait; `pending()` is nonblocking; `forever()` can occupy a dedicated thread | It cannot inject events into crossterm. Thread/channel integration or bounded crossterm polling still needed. `handle().close()` wakes a blocked iterator for shutdown/join. |
| signal-hook `low_level::pipe` plus flags | Makes a caller-owned pipe/UnixStream readable | Ideal for a caller-owned poll/ppoll loop. Signal-handler bytes are wake tokens, **not signal identities**. Register flag first, pipe second; drain pipe before checking flags. Nonblocking writes collate when full. 0.4.4 takes OwnedFd / Into<OwnedFd>. |
| libc signalfd | Pollable signal records in the same Linux FD loop as input/timerfd | Block watched signals; masks are per-thread, so arrange them before creating threads. Do not expect crossterm's SIGWINCH handler to run if SIGWINCH is consumed through signalfd. |
| libc ppoll with appropriate signal-mask handling | Atomically unblocks selected signals while waiting | Avoids the check-then-sleep race for a direct-handler loop; EINTR and recomputed deadlines need explicit handling. |

Evidence: signal-hook docs/source, registry source, signalfd and poll manuals. Register notification before terminal mutation so a handled exit can clean up partially initialized state; do terminal I/O/restoration in ordinary control flow, not in the asynchronous handler. Signal-hook replaces the default disposition and does not restore it just because subscriptions are removed. Register before additional threads to avoid the documented initial-registration chaining race. Signals may coalesce and multiple kinds have no portable arrival ordering. Its registry uses SA_RESTART on Linux. [S17–S19][S25]

**Important implementation caveat:** bounded crossterm `poll` is not a hard upper bound for every faulty/fragmented input path. In `mio.rs::try_read`, the inner TTY-read loop does not check elapsed timeout; EOF and read errors other than WouldBlock/Interrupted are not returned as fatal errors there. The parser can require additional bytes; a subsequent blocking TTY read can wait past the outer timeout. It also decides a standalone ESC using whether more bytes were in its current input chunk, so packet-fragmented arrow sequences merit later PTY acceptance checks. The size fallback can launch external processes. Therefore “atomic flag plus a 50 ms poll” is a feasible **normal-path** responsiveness mechanism, not proof of bounded signal latency or the agreed cleanup on all input failures. A direct owned nonblocking FD loop makes EOF/error/deadline handling explicit. No runtime crossterm fault test was performed in this factual session. [S6]

## 4. Clock and scheduling

**Documented:** CLOCK_BOOTTIME (Linux 2.6.39+) is nonsettable, monotonic and includes suspend. It has CLOCK_MONOTONIC's clock-adjustment characteristics, so it avoids wall-clock discontinuities but is not the unadjusted CLOCK_MONOTONIC_RAW clock. Consecutive readings can be equal. `clock_gettime` returns 0 on success, -1/errno on failure. libc 0.2.189 exposes the function, timespec and CLOCK_BOOTTIME (=7) without an optional clock feature. No privilege is required simply to read that clock. glibc 2.17+ provides clock_gettime in libc; older glibc needed librt. [S12][S13]

**Inference:** retain an integer seconds/nanoseconds or checked Duration representation and a small boundary around the unsafe libc call. Read at acquisition completion, including after a bulk proc read. Recompute 500 ms deadlines from BOOTTIME and skip elapsed slots; do not subtract wall time or the nominal poll interval. A BOOTTIME call failure is a clock failure, not permission to silently substitute different semantics. Rust `Instant` currently uses CLOCK_MONOTONIC on Unix and explicitly leaves suspend accounting unspecified. Crossterm's own PollTimeout uses Instant; that is appropriate for its internal wait bookkeeping, not for the traffic observation time required by ticket 04. [S6][S12][S13][S15]

**Documented/inference:** timerfd_create supports CLOCK_BOOTTIME since Linux 3.15, with NONBLOCK/CLOEXEC and absolute `TFD_TIMER_ABSTIME`. It can be polled alongside terminal and signal FDs; read returns an 8-byte native-endian expiration count. Coalesced/missed expirations can prompt **one fresh acquisition**, not that many fabricated observations. BOOTTIME does not wake a suspended machine; BOOTTIME_ALARM does and requires CAP_WAKE_ALARM. A finite crossterm wait followed by BOOTTIME rechecking also accounts for suspend correctly, but may wait out its remaining active-time timeout after resume rather than becoming immediately ready at an expired BOOTTIME deadline. No separate suspend detector is necessary for the agreed elapsed-time semantics. [S12][S14]

## 5. Cleanup and prior cursor visibility

### Input mode and handled failures

**Implementation:** crossterm saves the complete original termios in a process-global Mutex<Option<Termios>> after enabling raw mode succeeds; disabling raw mode reapplies that saved value and clears it only on success. Repeated enable calls are idempotent, not reference-counted independent sessions. `is_raw_mode_enabled()` reports that saved-state bookkeeping, not an OS query. The restore path reacquires a terminal FD; it does not hold a session-specific original FD and does not automatically run on drop/signals. It exposes separate commands for screen/cursor changes; its functions alone are not a terminal-session guard. [S6]

**Inference:** either approach needs staged session ownership: snapshot before mutation, register shutdown notification, record attempted/completed mutations, and attempt every applicable restore even if another cleanup operation fails. Partial output writes can have changed terminal modes despite a returned I/O error; a command error is not proof that nothing changed. A direct implementation can retain the exact original termios and terminal FD, and any fcntl flags it changes. Restoring termios does not restore emulator screen/cursor modes. The termios manual notes tcsetattr can report success for a partially applicable request; checking critical settings with tcgetattr is possible. [S6][S7][S9]

**Documented/inference:** catch_unwind catches unwinding panics only. The default panic hook prints to stderr **before unwinding/catching**, so catching alone does not satisfy “restore before reporting.” An implementation can install a temporary nonprinting/capturing hook before the UI, catch unwinding, perform best-effort cleanup, then report and restore the prior hook. Keep cleanup nonpanicking. `process::exit` bypasses Rust stack destructors; return an ExitCode after cleanup or explicitly drop/clean before exit. Signal handlers cannot safely invoke arbitrary Rust buffered I/O, allocation or mutex-based crossterm restoration. SIGKILL/SIGSTOP, aborting panics and vanished/unwritable terminals cannot carry a universal successful cleanup guarantee; this matches ticket 05's handled-exit limit. [S17][S25][S26]

### Screen, cursor position and cursor visibility are different state

**Implementation/documented:** on Unix, crossterm Enter/LeaveAlternateScreen emits `ESC[?1049h/l`; Hide/Show emits `ESC[?25l/h`; Save/RestorePosition emits ESC 7/8. `cursor::position()` obtains coordinates, **not visibility**. There is no public visibility-query API or saved prior visibility in the inspected cursor module. Terminal termios/TIOCGWINSZ describe kernel state; a PTY kernel is not an emulator's display-state database. Simply leaving the alternate screen or using SavePosition does not establish prior-visibility restoration for every terminal. [S7][S9–S11][S16]

Supported mechanisms on **xterm-compatible terminals that actually implement them**: [S10]

- **Query DECTCEM before changing it:** send `ESC[?25$p` (DECRQM), then parse `ESC[?25;Pm$y` (DECRPM). Pm=1 is set/visible, 2 reset/hidden, 0 unrecognized, 3 permanently set, 4 permanently reset. Restore the observed mutable state with ?25h/l. Permanent states are evidence of inability to change that mode, not a normal mutable snapshot.
- **Xterm private-mode save/restore:** `ESC[?25s` / `ESC[?25r` (XTSAVE/XTRESTORE) can preserve that value without an application-side query. This is a one-level per-mode cache, not a nested stack; other code saving mode 25 can overwrite it. The protocol alone gives no acknowledgement proving an unknown terminal supported the save.
- Xterm ?1049 uses the alternate buffer plus DECSC-style cursor save/restore and may be disabled by titeInhibit. It is a protocol operation, not a portable captured bitmap or a general stack restoring arbitrary pre-existing/nested alternate-screen state.

**Query-integration limitation:** crossterm's private-CSI parser recognizes `?…u` and `?…c`, not DECRPM `?25;…$y`; no public Event carries that reply. A custom visibility-query handshake cannot be implemented merely by sending it and then expecting `event::read()` to return its response. A bounded raw-byte handshake before constructing/using crossterm's global event reader is feasible, provided it preserves unrelated user input and handles timeouts, late replies and mixed response bytes. Competing raw reads alongside crossterm event reading are not supported. Direct input ownership can handle this in one parser; neither approach makes a nonresponding terminal respond. [S6][S10]

**Concrete counterexample (implementation, Linux v6.12):** the kernel virtual-console driver implements ?25h/l but has no mode-25 DECRQM response, XTSAVE/XTRESTORE, or ?1049 alternate-buffer switch. Its CSI parser ignores the intermediate `$` query, and csi_DEC_hl handles a limited list without 1049. `save_cur`/`restore_cur` copy `vc->state`, while visibility is `vc_deccm`, outside that saved state. Thus this is not just uncertainty about an undocumented crossterm feature: the generic Linux-TTY assumption includes a terminal unable to fulfill these xterm mechanisms. An isatty result establishes a TTY, not these capabilities; a TERM label is not a successful query. [S11]

**Blocker for the parent decision:** ticket 05 promises *prior* cursor visibility and prior screen restoration. The factual research cannot choose whether to constrain supported terminals/protocols, fail initialization when required state is unknowable, or agree a fallback (for example Show on exit). Those have different observable behavior and need human confirmation. Exact restoration is conditionally feasible on supporting terminals, **not impossible everywhere**, but neither crossterm nor direct termios+ANSI supplies it unconditionally. Do not silently replace this contract while implementing architecture. [S7][S10][S11]

## 6. Whole-list proc acquisition and raw name parsing

Read the existing [Linux interface enumeration and byte-counter semantics](linux-counters.md), especially its proc table, acquisition/failure section and consistency limits. Rechecked tagged Linux v6.12 `dev_seq_printf_stats`, `dev_seq_show`, and `dev_valid_name` against upstream source. [S20][S21]

- **Implementation:** `/proc/net/dev` has two headers followed by rows formatted `%6s: …` with the raw C-string name. Width 6 is a **minimum padding width**, not a six-byte truncation. RX bytes is numeric field 1 and TX bytes field 9 after the delimiter; there are 16 decimal statistics columns. The kernel obtains `dev_get_stats` for each emitted interface; one traversal covers the list. [S21]
- **Implementation:** `dev_valid_name` rejects empty names, names reaching IFNAMSIZ (16 in the UAPI), `.`/`..`, `/`, `:` and kernel whitespace. It does **not** require UTF-8 or all-printable ASCII; other control/non-ASCII bytes are possible. The proc name is not escaped. In that model the colon delimiter is unambiguous, and spaces before the name are padding. No locale/Unicode normalization should be used to identify it. [S21]
- **Inference:** acquire into Vec<u8>/a reusable byte buffer, split byte lines, remove only proc ASCII padding, retain the exact name bytes, and parse the ASCII unsigned counters with checked u64 conversion. `read_to_string`/lossy decoding can fail or alter identities. Use Unix OsStr/OsString bytes for argument/path identity where needed, and the already agreed `\xHH` escaping only at rendering. This adds no name-byte obstacle to bulk collection. [S21][S22]
- **Documented/inference:** read through EOF; proc seq_file may require multiple reads and can regenerate an overflowing buffer. Reopen for each acquisition or rewind a retained FD for a fresh traversal. Do not assume one read, a fixed-size buffer or atomic all-interface accounting/topology. Shared acquisition-completion timestamps are feasible under ticket 04. New names can be filtered against the retained startup list. [S20][S21]
- **Inference:** distinguish complete successful enumeration with an absent startup name from failed/incomplete acquisition. A read/truncation/parse failure is not evidence that the unparsed interfaces disappeared or had zero traffic. A global file failure can make all retained entries acquisition-failed; malformed attributable rows can be interface-local according to the eventual error boundary. No benchmark or hard “modest cost” threshold is established by this investigation; O(interfaces/output bytes) bulk work is feasible, not a proven latency budget. [S20]

## 7. Mechanism comparison and feasibility recommendation

| Concern | Crossterm 0.29.0, events only | Direct Linux termios + ANSI |
| --- | --- | --- |
| Keys | Existing CSI/SS3/modifier decoding and event model | Own incremental byte parser: arrows, q/Q, Ctrl+C, ignored Ctrl+Z; preserve partial/unknown sequences so trailing q does not become an accidental quit |
| Input mode | Saved global termios and raw enable/disable APIs | Snapshot/restore exact retained FD with libc; own unsafe/error checks |
| Wait/resize | Private mio loop and SIGWINCH; convenient poll/read API | Poll/ppoll input + self-pipe or signalfd + optional BOOTTIME timerfd; query TIOCGWINSZ on resize |
| Exit wakeup | Finite normal-path polling + flags, or more involved event-thread/async integration; limitations in §3 | Same caller-owned wait includes shutdown FD; EOF/EIO/HUP/error/deadlines can be explicit |
| Cursor/screen | Useful output commands but no prior-visibility query; custom handshake/private-mode commands needed | Same terminal-protocol limits; query bytes can share owned parser |
| CLOCK_BOOTTIME | Needs a separate clock boundary (libc is a small option) | libc exposes both clock and timers |
| Dependency/maintenance work | Larger audited graph; retains mature parser, but global input/cleanup limitations remain | Minimal Cargo graph; own terminal/parser/syscall correctness and terminal compatibility matrix |

**Inference/recommendation for feasibility:** synchronous operation needs no Tokio/async-std runtime. Both paths can provide ordinary interactive input/resize and suspend-aware observations. For a strict unified wake/error/query boundary, direct Linux FD ownership with libc 0.2.189 and either signal-hook 0.4.4 self-pipe notification or signalfd is a concretely feasible mechanism. For library-backed ordinary key parsing, crossterm 0.29.0 events-only is feasible with explicit Ctrl+C, external signal and staged cleanup integration, subject to the source-level fault/timeout caveat. These are mechanism recommendations, **not the human's selection**. The prior-cursor/support issue applies to both and must be carried into architecture/acceptance. [S6–S19]
